## 1. Цель работы

Подключить страницу со списком задач к учебному API: загрузка, добавление, изменение, смена статуса и удаление задач через сервер.

## 2. Реализация

### 2.1. HTTP-клиент

Взял `api-client.js` из ПР5 и добавил `method` и `body`. Разрешены GET, POST, PATCH, DELETE. Если есть тело — делаю `JSON.stringify` и ставлю `Content-Type: application/json`. На 204 возвращаю `null`. Тайм-аут и отмена остались как в ПР5.

### 2.2. Доменный API

В `task-api.js` добавил `createTask` (POST), `updateTask` и `setTaskCompleted` (PATCH), `deleteTask` (DELETE), `resetDemoData`. Каждый ответ проверяю функциями `isTask` / `isCategory`.

### 2.3. Состояния интерфейса

Перед запросом — `loading`, потом `ready` или `empty` (если задач нет), при ошибке — `error` с кнопкой повтора. Отмену запроса как ошибку не показываю.

### 2.4. Изменение данных

Все изменения идут через `runMutation`: блокирую кнопки, отправляю запрос, показываю сообщение и заново загружаю список с текущими фильтрами, потом снимаю блокировку.

### 2.5. Защита от устаревшего ответа

Перед новой загрузкой отменяю старую через `AbortController` и увеличиваю номер загрузки `loadNumber`. Ответ применяю, только если его номер последний.

## 4. Результаты проверок

### 4.1. Автоматизированные проверки Node.js

```text
Итог API: успешно 23, ошибок 0.
Итог модулей: успешно 33, ошибок 0.
Итог интеграции: успешно 14, ошибок 0.
```

### 4.2. Браузерные проверки

```text
Всего: 14. Пройдено: 14. Ошибок: 0.
```

Сначала было 13 из 14: падала «Корректная форма создаёт задачу с серверным id». Причина была в самой проверке — внутри `waitFor` вызывался `requireNode`, который сразу выбрасывает ошибку, если карточки ещё нет, и проверка не ждала ответа сервера. Заменил в этой строке `requireNode(doc, ...)` на `doc.querySelector(...)` (`checks/browser.checks.js:182`), что проверяется — не менял. После этого все 14 проходят.

### 4.3. Ручные проверки

| Сценарий | Ожидаемый результат | Фактический результат |
|---|---|---|
| API не запущен | Состояние ошибки и кнопка повтора | Ошибка «Нет соединения с учебным API», есть кнопка повтора |
| Пустая выборка | Сообщение empty, список без старых карточек | «По выбранным условиям задач нет.», найдено 0 |
| Двойное быстрое применение фильтров | Отображается результат последнего запроса | Показывается последний (модульная проверка 27) |
| Ошибка формы | Запрос не отправляется, поля получают сообщения | Запроса нет, у поля сообщение об ошибке |
| Смена статуса при `completed=false` | Задача пропадает | `PATCH /tasks/4` 200, затем `GET ?completed=false` 200, задачи 4 нет |
| Перезапуск API | Восстанавливается исходный набор | После перезапуска снова 12 задач |

## 5. Ответы на контрольные вопросы

1. **Почему `fetch` не отклоняет Promise при ответе 404?** Потому что ответ от сервера получен. Promise отклоняется только когда ответа нет вообще.
2. **Почему ответ 204 нельзя разбирать вызовом `response.json()`?** У него нет тела, будет ошибка разбора пустой строки.
3. **Чем состояние `empty` отличается от `error`?** `empty` — запрос прошёл, просто задач нет. `error` — запрос не удался.
4. **Зачем отменять предыдущий запрос при смене фильтров?** Чтобы старый ответ не пришёл позже и не перезаписал новый список.
5. **Почему после мутации список повторно запрашивается у API?** Данные хранит сервер, так на экране всегда то, что реально на сервере.
