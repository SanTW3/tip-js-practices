## Запуск

Из папки `practice-04`:

```bash

```

Приложение: `http://127.0.0.1:5504/`, свой вариант: `?dataset=variant`, проверки: `/checks.html`.

## Что сделано

- Из ПР3 перенесены `data.js`, `task-selectors.js`, `task-service.js`, `task-view.js`.
- В `task-service.js` добавлена `updateTask` — меняет только `title` и `priority`, `completed` не трогает.
- В карточку добавлена кнопка «Изменить» (`data-action="edit"`).
- `form-validation.js` — `validateTaskDraft`: проверяет id (число, положительное, не занято), название (1–100 символов после `trim`) и приоритет. DOM не использует.
- `task-storage.js` — `loadTasks`, `saveTasks`, `removeSavedTasks`, `isValidTaskList`. Данные хранятся как JSON `{ version: 1, tasks }`, ошибки перехватываются через `try/catch`.
- `main.js` — форма в двух режимах (добавление и редактирование), сохранение после каждой успешной операции, кнопка сброса.

Ключи хранилища: `tip-js-practice-04:demo` и `tip-js-practice-04:variant`.

## Отладка

Точка останова в `handleFormSubmit` на вызове `validateTaskDraft`. При добавлении 20 в черновике id был строкой `"20"`, после проверки — числом `20`. При повторном id 4 вернулось `{ ok: false, errors: { id: ... } }`, до `addTask` и сохранения дело не дошло.

## Вывод

Добавил форму с проверкой ввода и сохранение задач в `localStorage`. Понял, что HTML-проверки мало (пробелы проходят), что `localStorage` хранит только строки и что прочитанные данные надо проверять, а не верить им.
