## Эксперименты с формой и хранилищем

Страница `examples/forms-storage.html`.

| № | Прогноз | Результат | Объяснение |
|---:|---|---|---|
| 1. Пустое название | `submit` не произойдёт, браузер покажет сообщение. | Обработчик `submit` не вызван, журнал не изменился; `validity.valid = false`, `valueMissing = true`, сообщение «Please fill out this field.». | Нативная проверка `required` блокирует отправку ещё до события `submit`. |
| 2. Только пробелы | `required` пропустит, отклонит прикладная проверка. | `submit` получен; в журнале «прикладная проверка отклонила значение»; `validity.customError = true`, сообщение «Название не должно состоять только из пробелов.». | Для `required` строка из пробелов непустая. Правило «после `trim` не пусто» — прикладное, его ставит `setCustomValidity`. |
| 3. Корректные значения | Тип из `FormData` — строка, отправка отменена. | `defaultPrevented: true`, `typeof FormData title: string`, название сохранено как «Изучить формы» без краевых пробелов. | `preventDefault` отменяет перезагрузку страницы, `FormData` всегда даёт строки, `trim` нормализует. |
| 4. Чтение значения | `getItem` вернёт строку JSON. | `typeof localStorage value: string`; `JSON.parse` вернул объект `{ title, priority }`. | `localStorage` хранит только строки, объект восстанавливается через `JSON.parse`. |
| 5. Повреждённый JSON | `JSON.parse` выбросит исключение. | «JSON.parse завершился ошибкой: Expected property name or '}' in JSON at position 1». | Поэтому разбор находится внутри `try/catch`. |

Итог: HTML-проверка контролирует структуру ввода, прикладная — правила модели (пробелы, уникальность id), а ошибка разбора JSON — это сбой сохранённых данных, который обрабатывается отдельно.

## Организация кода

| Файл | Ответственность |
|---|---|
| `task-service.js` | Операции над задачами, в том числе `updateTask`: проверяет id, наличие задачи, название и приоритет (через `createTask`), меняет только `title` и `priority`, `completed` сохраняется. |
| `form-validation.js` | `validateTaskDraft(draft, tasks, editingId)` — чистая функция: не трогает DOM и `localStorage`, возвращает `{ ok: true, value }` или `{ ok: false, errors }`. |
| `task-storage.js` | `isValidTaskList`, `loadTasks`, `saveTasks`, `removeSavedTasks`. Получают `storage` аргументом, перехватывают исключения, хранят `{ version: 1, tasks }`. |
| `task-view.js` | Карточки, список, сводка, пустое состояние. |
| `main.js` | Состояние (`currentTasks`, `currentFilter`, `editingId`), форма, обработчики, вызовы сервиса, сохранения и отрисовки. |

Поток операции: `submit` или `click` → `validateTaskDraft` → `addTask` / `updateTask` / `setTaskCompleted` / `removeTask` → при `ok` новый `currentTasks` → `saveTasks` → `renderApp`. `renderApp` хранилище не трогает, фильтр и режим формы не сохраняются.

Ключи: `tip-js-practice-04:demo` и `tip-js-practice-04:variant`, для проверок — `tip-js-practice-04:checks:*`. Сброс удаляет только текущий ключ через `removeItem`, `clear()` не используется.

## Вывод

Список задач из ПР3 дополнен формой создания и редактирования и сохранением в `localStorage`. Проверка ввода разделена на два уровня: HTML-ограничения (`required`, `min`, `maxlength`) и чистую функцию `validateTaskDraft`, которая проверяет правила модели. После проверки данные всё равно меняет сервис (`addTask`, `updateTask`). Хранилище вынесено в отдельный модуль: данные записываются как JSON с версией, при чтении проверяется вся схема, ошибки перехватываются, а при повреждении загружается исходный набор с предупреждением. Пройдены 35 + 27 + 23 проверки, общий сценарий и сценарий варианта 5 совпали с ожиданиями.
